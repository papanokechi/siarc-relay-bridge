## 3. The search space, fixed now

A relation is sought of the form

```
    C  =  ± 2^{a} · 3^{b} · π^{c} · Γ(1/3)^{d} · Γ(1/6)^{e} · e^{f}
```

as a multiplicative relation, i.e. PSLQ is run on the **logarithm vector**

```
    v = [ log C, log 2, log 3, log π, log Γ(1/3), log Γ(1/6), 1 ]
```

seeking integers `(m, a, b, c, d, e, f)` with `m ≠ 0` and

```
    m·log C + a·log 2 + b·log 3 + c·log π + d·log Γ(1/3) + e·log Γ(1/6) + f = 0.
```

**Rationale for this basis, stated before running it.** `ξ₀ = 2/√3` and
`ζ* = 4/√3` are generated by `2` and `√3`; `2πi` is already explicit in the
normalisation; `Γ(1/3)` and `Γ(1/6)` are the gamma values attached to the
`β₂ = 3` / third-root structure that produces `√3` here, and are the standard
companions of `3` in constants of this family. `e` is included so that a
relation of exponential type cannot be missed. The vector is **7 long and fixed
now**; no constant may be added to it after a failed run.

### 3.1 Bounds, fixed now

- coefficient height bound `H = 10^6` (any relation with `max|coeff| > H` is
  **rejected as not found**, not reported);
- `|m| ≤ 12`;
- PSLQ working precision `dps = 120`, input vector built from `C` truncated to
  `D_trust = 100` digits.

### 3.2 The digit-cost margin — the criterion that makes this falsifiable

A PSLQ relation of `n` terms with coefficients of height `H` costs roughly
`n · log10(H)` digits to specify. A relation is **numerology unless the input
precision greatly exceeds that cost.**

```
    cost  =  n · log10(max |coeff|)        (n = number of NON-ZERO coefficients)
    ACCEPT requires  cost  ≤  0.40 · D_trust  =  40 digits.
```

A relation costing more than 40 digits against a 100-digit input is
**reported as NOT ACCEPTED, with its cost**, however pretty it looks.

---

## 4. Acceptance criterion (all four required)

A closed form is **ACCEPTED** only if:

1. PSLQ returns a relation within the bounds of §3.1;
2. its digit cost satisfies §3.2 (`cost ≤ 40`);
3. **stability**: the identical relation is returned when the run is repeated
   with the input truncated to `90` digits and to `80` digits, at the same
   working precision. A relation that changes with input truncation is an
   artefact;
4. **reconstruction**: the closed form, evaluated independently at `dps = 150`,
   reproduces the stored `C` to `≥ 95` digits.

Label if all four hold: **VERIFIED** — a numerically recognised closed form at
stated precision. **Not PROVEN.** No derivation is attempted in Stage 5, and a
PSLQ hit is not a proof. This label is fixed now and may not be raised because
the agreement is impressive.

## 5. What a NEGATIVE result looks like, pre-registered

Per the operator: *"no closed form found" is only meaningful against a stated
search space.* The template is `op:cc-median-resurgence-execute`'s own falsifier
discipline.

If no relation satisfies §4, the reported claim is **exactly** this, and is
labelled **VERIFIED** (it is a verified statement about a search, not a
statement about `C`):

> **NOT FOUND.** No multiplicative relation of the form
> `C = ± 2^a 3^b π^c Γ(1/3)^d Γ(1/6)^e e^f` exists with all coefficients
> bounded by `10^6`, `|m| ≤ 12`, and digit cost `≤ 40`, against `C` known to
> 100 decimal digits. Search space: the 7-vector of §3. This **excludes that
> space**; it is **not** evidence that `C` has no closed form, and in
> particular says nothing about spaces containing other gamma values, other
> algebraic irrationalities, polylogarithms, or `ζ(3)`.

The negative result must report: the search space, the bounds, `D_trust`, and
the smallest digit cost achieved by any rejected candidate — so a later fire can
tell whether the space was nearly hit or badly wrong.

**A negative result is a result and is reported with the same prominence as a
positive one.** Widening the space after a negative run is permitted only as a
*new, separately pre-registered* search — never by editing this file.

## 6. Vacuity pre-check — runs BEFORE the real search

The failure mode specific to PSLQ is a search space rich enough to fit
**anything**. If the basis of §3 admits a low-cost relation for an arbitrary
number of the same size, then finding one for `C` means nothing.

**Pre-check.** Run the identical pipeline, at identical bounds and identical
precision, on three **decoys**:

- `C_d1 = C · (1 + 10^{-30})`   (a near-miss: must NOT be recognised)
- `C_d2 = ` the first 100 digits of `8.1` followed by digits of `π` past the
  decimal point — a number of the same magnitude with no structure
- `C_d3 = C + 1/7`

**FIRES (and Stage 5 is void, halt and report) if:** any decoy yields a relation
meeting all of §4's bounds and the §3.2 cost criterion. That would show the
space fits arbitrary numbers at this cost, and no positive result on `C` could
be distinguished from it.

**Positive control, also required.** Run the identical pipeline on a number
with a *known* closed form inside the space — `C_k = 4 π² / (3 Γ(1/3))` — and
confirm it **is** recognised, at cost well under 40. If the positive control
fails, the pipeline is broken and no negative result may be reported.

The pre-check must therefore produce: **3 decoys rejected, 1 control accepted.**
Any other outcome halts Stage 5.
